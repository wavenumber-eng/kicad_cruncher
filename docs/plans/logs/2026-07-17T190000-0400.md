## Parity independently verified (stronger than the shipped test)

The shipped parity test covers taillight F.Cu/B.Cu. This reviewer additionally
ran exact styled-output equality direct-vs-cached on:

- 4-ch-backplane F.Cu and B.Cu: equal, drill counts 2171/2171, byte-identical.
- Speedy Processing Module, **all 10 copper layers**: equal on every layer.

One theoretical gap was investigated and closed empirically: the compositor
renders with `#000000` default fill/stroke while the old direct call passed
`#B8B8B8`, and `_apply_pcb_review_theme` recolors only categorized elements
(drill/edge/track/zone/pad) — an uncategorized element colored by the render
default could differ between paths, and the probe's byte-total evidence could
not catch it because both color strings are seven bytes. Measurement shows the
enriched renderer emits explicit per-record colors: thousands of `#000000`
occurrences appear identically in both paths (e.g. Speedy F.Cu 4215/4215), so
no element inherits the differing default. Parity is structural for enriched
output, not a fixture coincidence. Recommendation (non-blocking): extend the
parity test to one multi-layer fixture (e.g. Speedy) so this stays covered
without reviewer reruns.
