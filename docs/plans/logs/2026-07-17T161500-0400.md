# Log: project-api-fit-research

## Project/API Fit Research

Research basis:

- `design/dr` builds a full `KiCadDesign` and full design JSON, then renders review SVGs by calling `pcb.to_svg()` once per copper layer in `src/py/kicad_cruncher/kicad_cruncher_cmd_design.py`.
- `pcb-svg` loads the board once and already uses `PcbSvgCompositionRenderCache` plus `render_pcb_svg_composition()` in `src/py/kicad_cruncher/kicad_cruncher_cmd_pcb_svg.py` and `src/py/kicad_cruncher/kicad_cruncher_pcb_svg_compositor.py`.
- `pcb clean` uses `KiCadPcb(...)` for dry-run report, apply, and mutation paths in `src/py/kicad_cruncher/kicad_cruncher_pcb_clean.py`.
- `pcb-layer-step` uses `KiCadPcb.from_file()` before geometry extraction in `src/py/kicad_cruncher/kicad_cruncher_cmd_pcb_layer_step.py`.
- BOM/PnP/JLC workflows load `KiCadManufacturingDesign`, which currently wraps `KiCadDesign.from_file()` and then uses schematic and placement data.

Decisions by surface:

| Surface | Decision | Rationale |
| --- | --- | --- |
| `design/dr` PCB review SVGs | Investigate a Cruncher-local command-scoped render cache after independent review. | The current path repeats `pcb.to_svg()` per copper layer. The post-floor SVG loop is still about 4.4s-4.9s for only two layers, so the full all-layer command can still spend meaningful time there. This is a local composition/lifetime problem and does not require a new public Monkey API. |
| `design/dr` design JSON | Defer to upstream Monkey or a future explicit output option. | `design_json` remains the largest stage, but the command currently promises a design JSON artifact. Replacing it with projection or partial reads would change output semantics. |
| `pcb-svg` | No cache implementation selected from research alone. | This command already creates `PcbSvgCompositionRenderCache(pcb)` once per command invocation. Baselines are dominated by board load and selected composition. Extra caching would need view-specific evidence and mutation/lifetime tests. |
| `pcb clean` and daemon/plugin cleanup | Keep full mutable PCB model. | Dry-run and apply paths inspect or mutate the board. Projection/targeted reads do not preserve mutation semantics. Any optimization must be an early config gate, not a replacement read path. Daemon-wide caches are rejected unless explicit render/mutate/render invalidation tests are added. |
| `pcb-layer-step` | Keep full PCB model unless later measurements identify a narrow feature subset. | STEP extraction needs board geometry and classification. Projection is only plausible for a subset of feature modes; this plan has not measured a safe subset. |
| BOM/PnP/JLC | Defer broad refactor; document cost. | BOM can be schematic-centered, but current shared manufacturing model uses `KiCadDesign`. PnP and JLC need placement data. A split schematic-only BOM path is a future design task, not a cheap window from this evidence. |
| Project/projection APIs | Use in guidance, not as a hidden replacement inside existing full-output commands. | Monkey guidance established that projections help narrow family scans and memory, while broad/nested scans can equal or exceed full parse. Cruncher commands should expose or document the right read path rather than silently changing full-output commands. |

Result:

- The best local implementation candidate is `design/dr` reuse of the command-scoped SVG composition/cache pattern already used by `pcb-svg`, subject to output parity tests.
- Library-level parser/materialization work remains upstream Monkey follow-up work.
- Documentation should explain that the Monkey 2026.7.17 dependency already improves Cruncher parse-like workflows, but commands that promise full design/board artifacts still carry full-materialization cost.
