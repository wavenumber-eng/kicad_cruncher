# Log: implementation-scope-decision

## Implementation Scope Decision

Independent research review approved proceeding from research to implementation. Accepted implementation scope remains intentionally narrow.

Accepted for implementation:

1. Add a command-scoped cached PCB review renderer for `design/dr` so the per-copper-layer review SVG loop does not rebuild the same board render state for each copper layer.
2. Keep the cache lifetime within one `design/dr` command invocation. No daemon-wide, plugin-wide, process-wide, or mutable-board cache is accepted.
3. Add focused parity tests for the changed renderer and keep large-board timing evidence in the profiling helper/logs rather than brittle unit assertions.
4. Update durable guidance/backlog after implementation so users understand that `kicad-monkey 2026.7.17` already improves parse-like workflows while broad design-review artifacts still materialize full design data.

Required parity gates for implementation:

- Existing artifact manifest fields must be preserved: `file`, `layer`, `included_layers`, and `drill_slot_record_count`.
- Styled SVG output must preserve the design-review theme attributes, draw-order marker, enriched metadata needed by the styling pass, drill/slot record counts, and per-layer included physical layers.
- Parity must explicitly include SVG `viewBox` and coordinate framing/bbox semantics. The current `pcb.to_svg(layers=[layer, Edge.Cuts], profile=enriched)` path uses all-layer board framing before rendering each layer; the cached path must preserve that framing.
- Before/after implementation evidence must include at least one all-copper-layer run because the research baselines used only `--max-copper-layers 2` and the cache benefit should scale with copper layer count.

Rejected or deferred:

- No projection replacement for design JSON, netlisting, mutable `pcb clean`, daemon/plugin mutation paths, or STEP generation.
- No `pcb-svg` cache refactor from this evidence; it already uses `PcbSvgCompositionRenderCache` command-scoped.
- No daemon or plugin cache without a separately reviewed render -> mutate -> render invalidation contract and tests.
- No upstream parser, projection, pull-parser, native, or IR/SVG API work in this Cruncher plan.

Follow-up required after implementation:

- Record `design_json` cost as deferred explicit work in the Monkey follow-up backlog step. It is currently the largest `design/dr` stage on the measured 4-ch run, but the artifact is part of the current command contract.
