# Log: cheap-window-candidate-selection

## Cheap-Window Candidate Selection

Selection status before independent research review. No implementation has started.

| Candidate | Decision before review | Evidence and required follow-up |
| --- | --- | --- |
| Use the PCB SVG compositor cache or equivalent command-scoped render cache in `design/dr` | Proposed for implementation, pending independent review. | `design/dr` still calls `pcb.to_svg()` per copper layer. After the Monkey 2026.7.17 floor, two-layer SVG loop medians remain 4.887s on 4-ch and 4.399s on Speedy. Full all-layer design review can multiply this cost. Implementation must reuse or mirror `PcbSvgCompositionRenderCache` only within one command invocation and must include output parity tests against the current review SVG artifacts. |
| Keep render caches command-scoped unless daemon invalidation is designed | Accepted as a constraint, not a standalone implementation. | Existing compositor cache is command-scoped. Daemon/plugin lifetimes can observe mutations; no cross-command or daemon cache should be added in this plan. Any future longer-lived cache requires render -> mutate -> render invalidation tests. |
| Ensure `pcb-svg` only asks for needed families/views | Deferred unless independent review finds a missed narrow gate. | Current `pcb-svg` already uses `PcbSvgCompositionRenderCache`; post-floor totals show 12.189s on 4-ch and 9.644s on Speedy for two physical layers. More targeted view/family gating needs view-specific evidence; broad implementation is not selected now. |
| Avoid repeated board/project path resolution and repeated parse work within one command | Partially covered by the `design/dr` cache proposal; otherwise deferred. | The measured expensive repeat is SVG rendering/IR setup, not path resolution. No separate parse duplication was identified in the sampled commands. |
| Add progress or timing hooks for long silent work | Documentation or later UX candidate; defer from performance implementation. | Useful for operator feedback, but it does not reduce large-board runtime. It should not be mixed into the first performance patch unless implementation touches the same progress surface. |
| Use projection or targeted readers for narrow, read-only inventory workflows | Guidance-only for this plan. | The measured Cruncher commands are full-output, mutable, or broad render workflows. Projection remains appropriate for user-authored narrow scans and future explicit APIs, not hidden replacement inside `design/dr`, `pcb clean`, design JSON, or STEP. |
| Keep full-model APIs for mutable commands, broad render outputs, design JSON, netlist generation, and STEP generation unless measured evidence says otherwise | Accepted as design rule. | `pcb clean` dry-run tracks full PCB parse cost; apply/mutation safety requires the mutable board. `design_json` is a promised artifact. STEP and PnP/JLC need broad board or placement data. |
| Move deeper parser, projection, IR/SVG, pull-parser, or native acceleration needs to Monkey follow-up backlog | Accepted as future upstream work. | The Monkey 2026.7.17 floor already improved parse-like Cruncher workflows by about 1.25x-1.39x on the sampled boards. Remaining full-materialization costs belong in upstream Monkey unless Cruncher exposes a narrower contract. |

Proposed implementation scope after review:

1. Add a command-scoped cached PCB review renderer for `design/dr` that preserves the current artifact manifest, included layers, styling pass, drill/slot count extraction, and SVG output semantics.
2. Add focused tests that compare current and cached review SVG behavior on a small fixture and include a large-board timing probe update only as evidence, not as a brittle unit test.
3. Update CLI/API guidance to tell users when the Monkey 2026.7.17 floor helps automatically and when broad Cruncher commands still materialize full design or board artifacts.

Deferred/rejected scope:

- No daemon-wide render or board cache.
- No projection replacement for mutable commands, design JSON, netlisting, or STEP.
- No `pcb-svg` refactor without more specific selected-view evidence.
- No upstream Monkey parser or native implementation in this Cruncher plan.
